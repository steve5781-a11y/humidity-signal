사용성·접근성 설계 근거

ISO 9241(사용성)과 WCAG 2.2(웹 접근성)를 이 서비스에 어떻게 적용했는지, 무엇을 고쳤고 어떻게 확인했는지 정리했습니다. 표마다 관련 기준 → 내 규칙 → 수정 → 확인 방법 → 실제 결과 순서입니다.

표준을 "모두 충족했다"고 주장하지 않습니다. 직접 확인한 것과 확인하지 못한 것을 나눠 적었습니다.

ISO 9241-11 · 사용 맥락과 사용성 목표

측면이 서비스의 목표확인 방법실제 결과
사용자·과업·환경하우스 관리자가 작업 중에 습도 상태를 판단하고 조치. 보드 옆 PC, 주변 소음 있음홈 페이지에 사용자·과업·맥락을 적고 설계 결정마다 근거로 사용정리함 (홈)
효과성LED·LCD·대시보드가 같은 상태를 가리킴보드에 기준값을 바꿔 4가지 상태를 일부러 만들고 눈으로 비교일치함 (2026-10-29, 실물)
효율성화면을 보자마자 3초 안에 상태 판단첫 화면 맨 위에 가장 큰 글자로 습도·상태 배치다른 사용자 시간 측정 못 함
만족도경보가 귀찮지 않음사용자 의견 반영: 적정일 때 조용, 소리 작게, 부저 끄기 버튼"소리 크기 적당함" (제작자 확인)

ISO 9241-210 · 사람 중심 설계 반복 기록

실물 보드를 써 보며 나온 의견을 바로 고치고 다시 확인하는 과정을 반복했습니다.

회차써 보니 나온 문제·의견수정다시 확인한 결과
1건조를 파랑으로 보여 주니 "건조 = 노랑"이 더 자연스럽다건조 = 노랑(빨강+초록 절반), 적정 = 초록, 높음 = 빨강보드 출력 [80,40,0] 확인
2측정 전·센서 오류 때 불이 꺼져 고장처럼 보인다꺼지는 대신 파랑 = "측정 중·센서 확인"재시작 1초 뒤 파랑 → 상태색 확인
3습도가 바뀔 때 화면을 안 보면 모른다부저 추가: 낮음 2번, 높음 3번, 바뀔 때만상태 전환마다 울림 확인
4소리가 너무 크고 적정일 때도 울린다짧게(60 ms)·작게(20 %) 울리고, 원인이던 배선(부저 +가 5V)을 회로도로 바로잡음적정일 때 조용함, 크기 적당함
5색이 기대와 다르게 나온다 (초록 자리에 빨강)핀을 하나씩 켜는 시험 프로그램 + 그림 배선도로 배선 오류를 찾음D5 빨강 · D6 초록 · D9 파랑 확인
6실내 기준(40–70 %)과 딸기 기준(60–85 %) 중 무엇?서비스 목적(딸기 하우스)에 맞춰 60–85 %로 확정, 화면에서 바꿀 수 있게 유지기본값 60/85 적용
7능동형 부저를 핀에 바로 연결하면 위험 (강의 안전 수칙)D8과 부저 + 사이에 1kΩ, 대시보드에 "보드 부저" 끄기 버튼저항 넣은 뒤 소리 크기 다시 확인 필요
8노랑(빨강+초록)이 모듈에서 빨강·초록 두 점으로 따로 보여 "건조"로 읽히지 않는다섞은 색을 없애고 한 가지 색만: 건조 = 파랑, 측정 중·센서 확인 = 파랑 깜빡임(0.5초 간격)보드 출력 [0,0,80] 확인 (2026-10-29)

ISO 9241-110:2020 · 상호작용 원칙 7가지

과업 적합성첫 화면에 지금 습도·상태·할 일만 크게설정은 오른쪽, 기록·도움말은 아래로대시보드 첫 화면 확인맨 위 카드에 습도·상태·뜻 표시
자기 설명성상태마다 뜻과 할 일을 문장으로"보드 신호등 출력"(명령값)과 실제 LED를 구분해 설명시뮬레이션으로 적정·높음·낮음을 차례로 만듦상태별 문장·색·LED 설명 표시 (2026-10-29)
기대 부합성보드 LED·LCD·화면이 같은 색·같은 낱말건조 = 파랑으로 보드·화면 통일, 메뉴를 모든 페이지 같은 자리에실물 보드와 화면을 나란히 비교일치함 (2026-10-29)
학습 용이성보드 없이도 연습 가능시뮬레이션 연결 방식, 도움말 위치 고정시뮬레이션으로 연결·설정 시험보드 없이 모든 화면 동작
제어 가능성사용자가 끄고 멈출 수 있음화면 갱신 멈춤, 신호등·보드 부저·화면 알림음 각각 켜고 끄기버튼마다 응답(ack) 확인실물 보드: BUZZ 0/1 적용, BUZZ 5 거절 (2026-10-29)
사용 오류 견고성잘못된 값을 보내기 전에 막고, 보드도 다시 검사틀린 칸 표시·이유·고치는 법, 보드는 error로 거절낮음 50 / 높음 30 보내기보드가 low_not_below_high로 거절
사용자 참여작물·취향에 맞게 바꿀 수 있음기준값·밝기 조절, 딸기 초기값 한 번에 되돌리기기준을 바꾸고 색 변화 확인바꾼 기준으로 판단

자동 검사 (axe-core)

2026-10-29, 배포한 주소(GitHub Pages)에서 axe-core 4.10.2로 WCAG 2.0·2.1·2.2 A·AA 규칙을 검사했습니다(Chrome, 밝은 테마).

  • 홈·옵션 추천·설계 근거·대시보드: 위반 0건. 대시보드는 시뮬레이션으로 적정·높음·낮음 상태를 각각 띄운 뒤에도 0건.
  • 회로도: 처음 검사에서 단계 번호 글자 대비 4.11:1(기준 4.5:1) 1건 → 글자색을 #9a4a10(약 6.3:1)으로 바꿔 고침.
  • 자동으로 판정하지 못한 항목: 배경이 겹치는 글자의 대비(color-contrast 일부) — 위 표의 계산값으로 대신 확인.
  • 검사하지 않은 것: 어두운 테마, 화면 낭독기 낭독, 200 % 확대.
